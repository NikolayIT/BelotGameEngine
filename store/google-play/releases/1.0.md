Native testing used **BlueStacks Test / Pie64_2**, `127.0.0.1:5575`, Android 9 / API 28. The derived APK SHA-256 was `fa15cac28c1cfe340bc5a7639ac98a07aba5d3afe91bbfbfb2882b0aaeb31db5`. It was signed with Test's existing debug certificate (`ce234f2571303ab23456abc43a15b2968ba354f18c39061d78352bd7acb692ea`) solely to update without deleting local data. **This checks release content, not production signing installation or Play delivery.** Test returned to Bulgarian Home at its original 1920 × 1080, 240 dpi, font 1.0 and no immersive override. The Tower was untouched.

The 16 KB result is a **static binary/packaging check**, not execution on a 16 KB device. Each RELRO covers a complete writable LOAD segment; rounding its protection to 16 KB touches no mutable data. Android's loader explicitly handles this safe case, so an unrounded RELRO endpoint alone is not treated as a failure. References: [Android page-size checks](https://developer.android.com/guide/practices/page-sizes#elf-alignment), [Bionic RELRO handling](https://android.googlesource.com/platform/bionic/+/android16-qpr2-release/linker/linker_phdr_16kib_compat.cpp).
